# Ответ клиенту и информация специалисту

С 15.10.2026, промпт `support-v1.1-audiences`. Один LLM-вызов, модель и провайдер прежние. Пользователь указал конкретный дефект: клиент уже пишет в поддержку, поэтому предложение «обратитесь в службу поддержки» не помогает ему и не является готовым ответом оператора.

Результат разделён на два поля строгой схемы:

- `draft` — только текст от лица поддержки, адресованный клиенту, на языке обращения. Без внутренних пояснений о базе, модели или необходимости найти другого оператора.
- `operator_note` — внутренняя заметка на русском: почему полного ответа нет, какие сведения нужно проверить. `unknowns` перечисляет конкретные недостающие факты для специалиста.

| Состояние | Текст клиенту | Информация специалисту | Действие в MVP |
|---|---|---|---|
| `draft` | Полный подтверждённый ответ с цитатами рядом | Только если полезна | Можно принять или отредактировать после проверки |
| `refuse` | Вежливый отказ, например от торгового совета | При необходимости | Можно проверить и принять; выдуманных цитат нет |
| `partial` | Только полезная подтверждённая часть | Что осталось неизвестным и что проверить | Явно неполный результат, требуется передача человеку |
| `abstain` | Пустое поле, без кнопки копирования | Конкретный пробел и необходимая проверка | Требуется человек; результат нельзя принять как клиентский ответ |

Пример: вопрос о точной комиссии USDT. Клиентский черновик отсутствует. Заметка специалисту: «В базе нет комиссии за вывод в USDT. Проверьте актуальный тариф и его применимость к операции, затем подготовьте ответ клиенту». Новую комиссию или внутреннюю команду модель не придумывает.

При смешанном вопросе о пополнении и комиссии клиентский блок содержит подтверждённые шаги пополнения, а внутренний — недостающую комиссию. Кнопка называется «Копировать часть ответа»; этот результат не считается полным. Общая инструкция не используется вместо ответа о личном статусе клиента.

Код проверяет непустой клиентский текст для готового ответа, отсутствие его у `abstain`, наличие внутренней заметки и списка пробелов у неполного результата. Ответ с оставшимися unknowns не принимается за готовый. Ошибка формата или провайдера даёт внутреннюю заметку без клиентского черновика. API блокирует accept/edit для неполного ответа; кнопка передачи сохраняет локальную отметку, реальной отправки или CRM-очереди по-прежнему нет. Закрытие пробела и подготовка окончательного ответа остаются работой оператора вне текущего процесса генерации.

Старые отчёты сохраняются как исторические, новый формат не приписывается им задним числом. В текущем рабочем интерфейсе `abstain` не показывается как клиентский черновик и для старой записи. Это отдельное оформление аудитории через поля JSON, без ещё одного агента; структурирование ответа соответствует [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Проверено на подставных ответах и пяти живых синтетических обращениях: USDT-комиссия, пополнение, смешанный вопрос, личный KYC-статус, торговая рекомендация. Полные результаты — `reports/audience_smoke.json`; известный reported API cost — $0.0420247. Все пять прошли технические проверки; тексты отдельно просмотрены. Это development smoke, не независимая оценка смысловой точности или частоты ошибок.
