# Valetax · Support Studio

Локальный веб-MVP помощника поддержки для тестового кейса Valetax. Python/FastAPI + React/Vite, модели **OpenAI через OpenRouter**. Классифицирует обращение, готовит ответ по четырём страницам базы знаний с цитатами либо указывает специалисту, каких данных не хватает. Все ответы проверяет оператор; отправки клиенту и решений по счёту нет.

В приложении шесть разделов: чат, база знаний, устройство системы, эксплуатация, тестирование и интерактивная экономика. Интерфейс содержит работу с обращением, факты о реализации, результаты и планы расширения. Исследовательские материалы и источники решений сохранены отдельно в `research/` и `docs/`. Дизайн опирается на IBM Carbon и локальные шрифты IBM Plex.

## Быстрый запуск без API-ключа

Нужны **Python 3.12+**, **[uv](https://docs.astral.sh/uv/getting-started/installation/)** и **Node.js 22+ с npm**. В GitHub Actions проект проверяется на Python 3.12 и Node.js 22.

```bash
git clone https://github.com/donaldbaiden/valetax-support-studio.git
cd valetax-support-studio
uv sync --locked
uv run python scripts/start.py
```

Открыть **http://127.0.0.1:8000**. Первый запуск сам установит frontend-зависимости через `npm ci` и соберёт интерфейс. Нужен интернет для установки зависимостей. Остановить сервер — `Ctrl+C`.

В свежем клоне ключа нет, поэтому приложение работает в явно обозначенном **демо-режиме с фиксированными шаблонами**, без вызовов LLM и расходов API. База знаний, схемы, сохранённые результаты тестирования и калькулятор экономики доступны без ключа. Сохранённые live-отчёты относятся к прошлым прогонам и не означают, что модель подключена в вашем запуске.

## Подключение OpenRouter

Из корня проекта:

```bash
cp .env.example .env
```

Открыть `.env` в редакторе и заполнить `OPENROUTER_API_KEY` своим ключом. `COPILOT_MODE=auto` включает живые вызовы при наличии ключа. Модель задаётся через `OPENROUTER_MODEL`; по умолчанию — `openai/gpt-6.1-sol`, выбранная для baseline. Доступ к этой модели зависит от аккаунта OpenRouter; можно указать другую доступную модель OpenAI с поддержкой строгого JSON Schema и повторно проверить качество. Модели других семейств адаптер отклоняет.

После изменения `.env` перезапустить приложение той же командой:

```bash
uv run python scripts/start.py
```

Живые запросы в чате и запуски live-тестов оплачиваются через OpenRouter. При отказе провайдера интерфейс покажет причину и необходимость ручной обработки. Сбой живого вызова не подменяется демо-ответом.

`.env` исключён из Git. В репозитории есть только `.env.example` с пустым ключом; ключ не передаётся браузеру, не возвращается API и не нужен в GitHub Actions. Локальные данные из `runtime/`, окружения и сборки тоже не публикуются. Сервер привязан к `127.0.0.1`; эта версия рассчитана на локальную работу без авторизации.

`COPILOT_MODE=demo` принудительно включает шаблоны даже при наличии ключа. В интерфейсе также можно выбрать явное демо.

## Разработка и возможные проблемы запуска

Для разработки в двух терминалах:

```bash
uv run uvicorn copilot.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload --reload-dir backend
npm --prefix frontend run dev
```

Frontend-dev: http://127.0.0.1:5173. API-документация: http://127.0.0.1:8000/docs.

- `uv` или `npm` не найден: установить зависимости, указанные выше, и заново открыть терминал.
- Порт 8000 занят: остановить предыдущий экземпляр. Для другого порта запустить backend вручную, например `uv run uvicorn copilot.main:app --app-dir backend --host 127.0.0.1 --port 8001`, и открыть `http://127.0.0.1:8001`.
- После обновления проекта выполнить `uv sync --locked` и `npm --prefix frontend ci`; команда запуска пересоберёт изменившийся интерфейс.
- Модель недоступна: проверить разрешения аккаунта, баланс, имя модели и сообщение об ошибке. Демонстрация без API доступна в режиме `demo`.

## Проверка

```bash
uv run pytest -q
uv run python scripts/evaluate.py --mode demo --subset all
uv run python scripts/evaluate.py --mode live --subset smoke
```

Live-eval выполняет платные вызовы с настроенным ключом. Полный набор: `--subset all`. Кнопка в интерфейсе запускает восемь smoke-случаев. В UI доступны сохранённые отчёты и все 32 synthetic-сценария.

[Что проверяется сейчас, как читать отчёт и план дальнейшего тестирования](docs/testing.md). В интерфейсе показаны ожидания и фактические результаты по каждому сценарию, все повторы и область применения каждой метрики. Экспертная оценка и пилот отмечены как следующие этапы.

Проверены 53 сервисных теста. Первый полный live baseline: **28/32** технических сценариев, категории **32/32**, маршруты **30/32**, reported API cost **$0.329390**. Исходный отчёт сохранён отдельно. После исправления ложной блокировки отказов: повторный development smoke **8/8**. Это разные прогоны, их нельзя объединять в новый независимый score. Смысловая точность и production-ROI пока не измерены. В пакетном запуске latency включает ожидание очереди; в новых traces очередь и provider latency разделены.

## Решения и ограничения

[Реализация, результаты, ограничения и расширения](docs/implementation.md) · [Схемы расширений, метрики и резервные модели](docs/architecture_extensions.md) · [Обоснование дизайна](docs/design.md) · [Актуальный одностраничный business case](docs/business_case.md).

[Phase 2: очередь, обработчики, расчёт нагрузки и рост KB/SOP](docs/scaling.md) · [Повторный аудит практик и исправления](research/08_practices_reaudit.md).

- Четыре страницы и исходные HTML сохранены в `data/kb`; формулировки и ошибки не исправлены молча. Навигация/footer исключены из модельного контекста, OCR картинок не выполнялся.
- JSON Schema и наличие цитаты проверяются кодом; логическое следование, полнота claims и смысл всего ответа — reviewer-ом.
- KYC/AML, complaints и конкретные состояния операций имеют отдельные маршруты. Обычный review не заменяет специалиста.
- История ограничена памятью текущего запуска. Передача reviewer локальная; реальные очереди, CRM, auth и долговременное хранение — точки расширения.
- Маскирование и сигнальные правила неполны. Нет утверждения о полной анонимизации или нулевом риске пропуска.
- У первоначально отложенных восьми случаев после разбора ошибок больше нет статуса нетронутого holdout. Для следующего сравнения нужен новый набор.

## Главные выводы

1. Роль предполагает ответственность за полный цикл: реализация, интеграция, эксплуатация, безопасность и доказательство бизнес-эффекта. Тестовое должно показывать эти решения в небольшом объёме.
2. Качество данных — часть задания. Ошибки исходной базы нельзя молча исправлять или дополнять сторонними политиками.
3. Цитата подтверждает утверждение только тогда, когда источник действительно его поддерживает. Наличие ссылки само по себе не доказывает корректность.
4. Различайте отказ давать торговый совет, отсутствие информации и передачу обязательного решения человеку.
5. При 10 000 тикетов в месяц основная экономическая переменная — фактически сэкономленное время оператора. Выбор более дешёвой модели вторичен относительно качества.

## Что известно и чего пока нет

- **Дано работодателем:** задача, четыре страницы, около 10 000 тикетов/месяц, ограничение 3–5 часов, сдача ссылкой на Git-репозиторий и последующий технический звонок.
- **Проверено в открытых источниках:** сайт AXISCoreTech, доступное содержание четырёх страниц Valetax, официальные тарифы выбранного LLM-провайдера. Ссылки стоят рядом с соответствующими фактами.
- **Предложено в этом пакете:** архитектура, таксономия, маршрутизация, тестовые сценарии, целевые пороги.
- **Допущения для расчёта:** время обработки, стоимость часа, доля применимых тикетов, принятие черновиков, инфраструктура и сопровождение.
- **Нужно получить в пилоте:** реальные тикеты, распределение языков, текущий AHT, точность, задержки, расход токенов, долю принятия и эффект на время.

MVP и первый eval выполнены. Следующий этап — экспертная смысловая разметка, новый holdout, уточнение routing SOP и пилотный замер времени операторов. Сценарные параметры экономики ещё не заменены production-данными.

После анализа предоставленного Telegram-экспорта план уточнён: рубрика до кода, единая версия контекста для генератора и проверки, claim-level evidence, ограниченный цикл исправлений по группам ошибок и измерение затрат времени на review. Публикации канала рассматриваются как рекомендации для критического разбора; условия тестового сохраняют приоритет.

Повторяемая проверка: `uv run python scripts/evaluate.py --mode demo --subset dev --repeats 3`. Для `--mode live` вызовы платные. Новые отчёты сохраняют каждый повтор и черновик с источниками; архивы — `reports/runs/`. Язык проверяется на 32 размеченных случаях, срочность на 2, тональность на 1; это узкое покрытие, не полная оценка качества.

[Формат ответа: клиентский текст и внутренняя заметка специалисту](docs/response_contract.md). Если данных нет, клиентский черновик не формируется; частичный ответ требует дополнения человеком.
